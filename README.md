## Overview

Health-information pages are a common source for patient-facing question answering. An answer can restate one detail correctly and add another that the page never states, and approving the whole answer hides the difference.

This repository holds the code, frozen protocol, prompts, raw judge outputs and analysis for a study of two locally run small language models that decide, claim by claim, whether a source passage **supports** the claim. It answers two questions:

1. **Detection.** How many human-confirmed *unsupported* claims do the judges flag?
2. **Stability.** How often does a verdict change under equivalent prompt wordings or different sampling seeds?

> The endpoint is *textual support by a supplied passage*. The results say nothing about clinical safety or the accuracy of the source.

## Headline results

Set B (controlled pairs), reference condition: prompt P1, seed 17.

| Judge | Sensitivity (95% CI) | Specificity | Prompt disagreement | Seed disagreement |
|---|---|---|---|---|
| Llama 3 8B | 0.588 (0.490 to 0.680) | 0.990 | 1.4% | 0.6% |
| Qwen2.5 7B | 0.765 (0.680 to 0.845) | 1.000 | 1.0% | 0.7% |

- **Stable but stably wrong.** 38 of 102 (Llama) and 21 of 102 (Qwen) unsupported claims were approved under all nine prompt-and-seed conditions.
- **Where they miss.** Contradictions are almost always flagged. Details added beyond the passage are mostly missed (Llama 4/34 flagged, Qwen 17/34). The error-type breakdown is exploratory.
- **No prompt-versus-seed claim.** Disagreement is at most 1.6% and the intervals overlap.
- **Set A is inconclusive.** Ordinary answers contained only 5 unsupported claims in 180, and neither judge flagged any, so sensitivity cannot be estimated there.

## Study design

| Item | Detail |
|---|---|
| Source | MedQuAD (Cancer.gov, NIDDK, NHLBI), 100 test questions plus 12 for development |
| Reference | Two blinded reviewers and one adjudicator, atomic-claim labels |
| Set A | Answers generated by the two models, 180 scored claims |
| Set B | 100 controlled pairs, one supported paraphrase and one minimally edited claim, 200 claims |
| Judges | Meta-Llama-3-8B-Instruct and Qwen2.5-7B-Instruct, Q4_K_M GGUF, llama-cpp-python 0.3.38 |
| Conditions | 3 prompts x 3 seeds (17, 29, 43), temperature 0.3, plus a greedy arm |
| Calls | 6,840 sampled and 2,280 greedy, all valid |
| Statistics | Paired question-level stratified bootstrap, B = 2000 |
| Protocol | Frozen 2026-11-26, Amendments 1 to 5 in `notes/` |

## Repository layout

```text
code/                 pipeline, prompts, parser, runner, analysis, figure and manuscript-fill scripts
data/
  items.csv           question, passage and claim records (no labels)
  labels/gold.csv     frozen adjudicated labels (reviewer identities not released)
  runs/               raw judge outputs and run manifests
  results.json        primary analysis output
  results_extra.json  exploratory analysis output
  FREEZE.json         SHA-256 of every frozen file
  items_excluded17.csv, runs_excl17/, results_exclusion.json
                      sensitivity analysis on the 17 refusal-type Set A claims excluded at the gold stage
  claims/, corpus/, setA/   segmented claims, selected questions and passages, generated answers
  labels/             gold labels, reviewer ratings (blind IDs) and adjudication
docs/                 annotation guide
notes/                protocol freeze record and amendments
h200_package/         optional GPU run package (not used for the reported results)
```

Source text is included only where source and repository terms permit. Otherwise identifiers and hashes are provided so the text can be recovered from MedQuAD.

## Reproduce

```bash
python3 -m venv .venv && source .venv/bin/activate
CMAKE_ARGS="-DGGML_METAL=on" pip install llama-cpp-python==0.3.38   # Apple silicon; use a CUDA build elsewhere
pip install -r code/requirements.txt

# checks
python code/test_keys.py
python -I code/analysis.py --selftest

# place the GGUF files in data/models/ and verify against data/models/MODEL_SHA256.txt
./run_pilot_and_full.sh full

# analysis
python code/analysis.py --gold data/labels/gold.csv \
  --runs data/runs/sampled_all.jsonl --greedy data/runs/greedy_all.jsonl \
  --out data/results.json
python code/analysis_extra.py --gold data/labels/gold.csv \
  --runs data/runs/sampled_all.jsonl --greedy data/runs/greedy_all.jsonl \
  --items data/items.csv --out data/results_extra.json --misses data/misses.csv

# sensitivity analysis: restore the 17 excluded claims (run on the Mac, needs the GGUF files)
./run_exclusion_sensitivity.sh
python code/analysis_exclusion.py data
```

Model file hashes: Llama `8ba9baf3...`, Qwen `dfce12e3...` (full values in the run manifests). Runs use fixed seeds, but other hardware or builds can change individual outputs.

## Notes on scope and honesty

- `analysis_extra.py` (error-type, miss-overlap and per-generator analyses) was written after the primary analysis and is exploratory.
- One post-freeze audit observation (claim `A-NIDDK-0000162-3-02`) is reported in the paper. Frozen labels were not changed.
- Set B was built by one member of the study team, so its edits may not match naturally occurring errors.
